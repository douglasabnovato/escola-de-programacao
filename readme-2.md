# 🎙️ Guia de Metodologia e Roteiro de Aula

Este guia define o padrão ouro para as aulas. Nosso objetivo não é apenas ensinar sintaxe, mas construir **didática consciente** através do alinhamento entre:
**Intenção → Código → Resultado → Explicação.**

---

## 🎯 Por que usamos este Roteiro?

Evitamos os três erros clássicos do ensino de programação:

1. ❌ Mostrar código pronto.
2. ❌ Falar muito sem construir (teoria vazia).
3. ❌ Construir sem explicar o raciocínio (digitação mecânica).

### O Fluxo da Aula em Tempo Real

1. **Você fala um conceito** (Explicação curta e intencional).
2. **Você escreve um trecho pequeno** (Construção incremental).
3. **O aluno vê nascer** (Engajamento visual).
4. **O navegador responde** (Feedback imediato).
5. **Você explica o que aconteceu** (Fechamento do loop mental).

## 🎓 TEMPLATE OFICIAL DE ROTEIRO

### 🔷 1. Identidade da Aula

- **Nome do Projeto:** (Ex: O Primeiro Formulário Inteligente)
- **Frase Memorável:** (Uma frase que conecte o código ao mundo real)
- **Nível:** `Básico` | `Iniciante` | `Intermediário` | `Avançado`
- **Duração Estimada:** 30 - 45 minutos
- **Projeto da Aula:** (Descrição objetiva do entregável)

### 🔷 2. Objetivos Cognitivos

Ao final da aula, o aluno será capaz de:

1. [Ação mensurável 1]
2. [Ação mensurável 2]
3. [Ação mensurável 3]
   > _Ex: "Explicar a diferença entre Padding e Margin usando a analogia da caixa de logística."_

### 🔷 3. Ativação Mental (O Problema)

- **Tempo:** 2–3 minutos
- **Pergunta Provocadora:** Gere tensão intelectual. O aluno precisa sentir a necessidade do conteúdo antes de recebê-lo.
- _Ex: "Por que seu layout quebra quando o texto do usuário é maior do que o esperado?"_

### 🔷 4. Fundamento (Mapa Mental)

- **Tempo:** 5–8 minutos
- **Explicação:** O que é, por que existe, onde se aplica e qual o erro comum.
- **Nota:** Sem digitar código ainda. Forme o conceito primeiro.

### 🔷 5. Construção Guiada (Pensamento Explícito)

- **Tempo:** 10–15 minutos
- **O Ciclo do Instrutor:**
  - 🧠 **Pensamento:** "O que eu preciso resolver agora?"
  - 🎯 **Decisão:** "Vou usar um Flexbox aqui porque..."
  - ⚠️ **Erro Provocado:** "Se eu esquecer essa propriedade, olha o que acontece..."
  - 🔧 **Ajuste:** "Corrigimos organizando desta forma..."
  - 🗂️ **Organização:** "Vamos limpar o código dividindo em blocos lógicos."

### 🔷 6. Refatoração Didática

- **Tempo:** 3–5 minutos
- **Comparativo:** Versão Simples ➡️ Versão Profissional/Organizada.
- **Objetivo:** Criar padrão mental de qualidade desde a primeira aula.

### 🔷 7. Consolidação Técnica

Faça 3 perguntas estratégicas para a turma:

1. O que mudou no comportamento da página?
2. Por que escolhemos esta técnica e não outra?
3. Em que situação este código poderia quebrar?

### 🔷 8. Aplicação e Desafio

- **Exercício Imediato (5-10 min):** Aplicação direta do que foi visto, sem copiar o exemplo anterior.
- **Desafio de Projeto (Para Casa):** Evolução do portfólio.
  - _Requisitos:_ Git, README estruturado e Deploy (se aplicável).

## 🧠 Estrutura Pedagógica  

Toda aula, sem exceção, deve conter estes 6 pilares:

| Pilar                      | Descrição                                 |
| :------------------------- | :---------------------------------------- |
| **Clareza Conceitual**     | O aluno sabe o "porquê".                  |
| **Construção Prática**     | O código nasce do zero.                   |
| **Erro e Ajuste**          | Debugar faz parte do aprendizado.         |
| **Organização Consciente** | Código limpo e pastas estruturadas.       |
| **Aplicação Real**         | Conexão com mercado/logística.            |
| **Evolução de Portfólio**  | Cada aula é um tijolo no GitHub do aluno. |

---

## ⚠️ Pontos de Atenção para o Instrutor

- **Evite:** Muita digitação repetitiva. Use snippets se necessário, mas explique-os.
- **Ritmo Cognitivo:** Monitore se o aluno está acompanhando ou apenas "copiando caracteres".
- **Autoridade:** Sua autoridade vem da capacidade de explicar o erro, não de escrever código perfeito de primeira.
